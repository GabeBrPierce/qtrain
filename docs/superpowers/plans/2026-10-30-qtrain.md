# QTrain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A KaiOS color-guessing game with 5-minute NIST-beacon rounds, instant practice rounds, Round/Day/Week/All boards, and KaiAds, hosted on GitHub Pages with a Cloudflare Worker + D1 backend.

**Architecture:** Pure game logic lives in `app/js/core.js`, written as an ES5-compatible IIFE that also exports via `module.exports`, so the browser (KaiOS 2.5, no modules), Node tests, and the Worker (bundled by wrangler/esbuild) share one copy. The Worker stores picks in D1, resolves rounds on a 1-minute cron from the NIST beacon, and proxies lizaonair for practice. The front end is static files under `app/`, deployed to Pages by a GitHub Actions workflow.

**Tech Stack:** Plain JS (Gecko 48 subset) + HTML/CSS, Node 22 `node:test` for unit tests, Cloudflare Workers + D1 + Cron Triggers via wrangler 4.x, GitHub Pages via Actions.

**Spec:** `docs/superpowers/specs/2026-10-30-qtrain-design.md`

## Global Constraints

- Browser JS must run on Gecko 48: no async/await, no ES modules, no optional chaining, no `??`, no object spread, no `Array.prototype.includes`/`Object.values`/`padStart`. Allowed: let/const, arrow functions, template literals, Promise, fetch.
- Screen 240x320; keys `SoftLeft`, `SoftRight`, `Enter`, `Backspace`, arrows, digits; desktop aliases Q = SoftLeft, E = SoftRight.
- Round length 300000 ms, closes on UTC multiples of 5 minutes; picks lock 10000 ms before close; pulse window 240000 ms after close, else void.
- Step at depth d: `max(1, round(32 * 0.6^(d-1)))`.
- Closeness: `100 * (1 - dist / 441.673)`, one decimal. Ties: earlier `submittedAt` wins.
- Color from beacon: first 3 bytes of pulse `outputValue`.
- NIST: `GET https://beacon.nist.gov/beacon/2.0/pulse/time/next/{closeMs - 1}` returns the first pulse at or after close (404 if not yet published).
- lizaonair: `GET https://lizaonair.com/qrng/?min=0&max=65535` with `Accept: application/json` → `{"value":n}`; ranges above 65535 are broken.
- Nickname: 3-12 chars, `^[A-Z0-9]+$` after uppercasing.
- Ads: KaiAds SDK `https://static.kaiads.com/ads-sdk/ads-sdk.v5.min.js`, `getKaiAd({ publisher: '0b1f52de-82bb-4c58-b2e4-1b125c046417', app: 'qtrain', slot: 'qtrain-us', ... })`; on app open and every 3rd result (practice and competitive share the counter); never on the pick screen.
- Manifest linked relatively (`manifest.webmanifest`), not `/manifest.webmanifest`.
- Free tiers only. No real accounts.

## Review Focus

- Clock skew on the phone: the client's idea of the open round can differ from the Worker's. The Worker is the authority; `/pick` for a non-open round returns 409 with `{error, openRoundId}` and the client switches to that round. (Task 5 test.)
- Double submit (key held, flaky network retry): second pick for the same round returns 409 `already_picked`, not a 500 or a duplicate row. (Task 5 test.)
- localStorage unavailable or throwing (private mode, quota): app still plays with in-memory state. (Task 3 test.)
- Beacon slow or down: rounds stay "waiting" up to 4 minutes, then void; boards exclude void rounds. (Task 4 test.)
- Picking at depth past 8: step stays 1, channels clamp at 0 and 255, no NaN or out-of-range hex. (Task 1 test.)

### Task 5: Worker API, D1 and cron

**Files:**
- Create: `worker/wrangler.toml`, `worker/schema.sql`, `worker/src/index.js`, `worker/src/db.js`, `worker/package.json` (devDependency `wrangler`), `test/api.smoke.sh`

**Interfaces:**
- Consumes: Task 4 functions, `core.openRoundFor`, `core.dayKey`, `core.weekKey`, `core.fromHex`, `core.rgbFromOutputValue`
- Produces (HTTP, JSON, `Access-Control-Allow-Origin: *`):
  - `POST /pick {playerId, nickname, roundId, hex}` → 200 `{ok:true, roundId}` | 400 `{error:'bad_input'}` | 409 `{error:'round_closed', openRoundId}` | 409 `{error:'already_picked'}`
  - `GET /round/:roundId?player=` → `{roundId, status:'open'|'waiting'|'resolved'|'void', hex?, pulseIndex?, players, top: [{nickname, hex, closeness, rank}] (10), me?: {hex, closeness, rank}}`
  - `GET /board/:period?player=` with period `day|week|all` (current UTC day/week) → `{period, key, top: [{nickname, tag, hex, closeness, roundId}] (10; `tag` = first 4 chars of player id, shown by the client only when two rows share a nickname), me?: {...same, rank}}`; best pick per player, excludes void rounds.
  - `GET /practice` → `{rgb:[r,g,b]}` from two lizaonair calls; 502 on failure.
  - `GET /now` → `{now, openRoundId}` (client clock sync).
- Schema: `players(id TEXT PK, nickname TEXT, created_at INT)`, `rounds(round_id INT PK, status TEXT, pulse_index INT, hex TEXT, day_key TEXT, week_key TEXT, resolved_at INT)`, `picks(round_id INT, player_id TEXT, hex TEXT, submitted_at INT, closeness REAL, rank INT, PRIMARY KEY(round_id, player_id))`, indexes on `rounds(day_key)`, `rounds(week_key)`.
- Cron `* * * * *`: for each round with `status='open'` and `round_id <= now`, fetch pulse, `choosePulse`, then either score + rank picks and set `resolved`, set `void`, or leave it.
